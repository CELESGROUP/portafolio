# Actualización V0.10
No modificar el inventario administrativo ni sincronizarlo automáticamente.
## Entregas
Agregar objetos a entregas en data/entregas.json con los campos:
id, vehiculo, marca, modelo, fecha, archivo_original, archivo_web, fuente, url_fuente, observacion, estado_publicacion.
Estados permitidos: BORRADOR, REVISION, PUBLICADO.
archivo_original debe ser un identificador interno no sensible del original conservado fuera del repo, nunca una URL privada ni un documento.
archivo_web es una ruta relativa a un derivado autorizado bajo VEHICULOS_VENDIDOS/02_WEB/ o assets/.
No incorporar nombres completos de clientes, teléfonos o información registral.
Solo PUBLICADO se exporta a la web; el JSON web excluye fuente, observacion y archivo_original.
## Historia
origen: null u objeto {texto, estado_publicacion}.
video: null u objeto {archivo_web, poster, estado_publicacion}.
fotografias: objetos {archivo_web, descripcion, estado_publicacion}.
Solo PUBLICADO se representa. Un video publicado necesita MP4 local, poster y autorización; no autoplay.
## Imágenes
Cambiar asociaciones solo en data/media.json. Conservar originales.
npm run build genera derivados WebP y reporte SHA-256. Revisar cada ficha y /qa/CCxxx en preview.
No inferir modelo, kilometraje o equipamiento desde una foto.
## Aprobación
Revisar diff, build, QA visual y funcional; solicitar aprobación antes de crear PR y fusionar. Esta entrega no cambia main ni el dominio de producción.
